I've implemented `map.mjs` at `/tmp/claude-0/-home-user-jev-discovery/c35f5c53-e272-5f13-8872-8508765d320f/scratchpad/heldout4/runs/expense-review-plugin-4-sonnet/map.mjs`. Design summary:

**buildState** — converts amount to USD with the given `fx_to_usd` rate in code (exact arithmetic, never asked of Jev), and carries `policy_text`, `category`, `city`, `receipt_attached`, `description` through by name. Returns `amount_usd: null` when the currency has no rate (a data gap, not a policy judgment).

**questions** — regex-extracts every `USD <number>` figure that appears in `policy_text` and uses those as the option set for three `choice` questions (`category_limit_standard`, `category_limit_highcost`, `receipt_required_threshold`), so Jev reads the exact stated figure rather than estimating a band. A `noul` (`high_cost_city`) reads whether the city is in the policy's high-cost tier. `alcohol_entertainment_included` asks whether the *description includes* alcohol/entertainment (not "is this a kind of expense that's disallowed" — the "includes" framing scored far better in measurement). Three more `choice` questions read what the policy itself says the *consequence* is for exceeding a limit, missing a receipt, or including alcohol/entertainment, and for an unaddressed category — so the map adapts to policy wording variants instead of hardcoding "over limit → needs_approval."

**decide** — all comparisons (amount vs. limit, amount vs. receipt threshold) happen in code against the Jev-read figures. Gates on each `choice`'s own probability and each `noul`'s value; any uncertain read escalates to `needs_approval`, never silently approves. `abstain` is reserved for the one case code truly can't resolve: an expense currency missing from `fx_to_usd`.

I traced the given example and a few variants (alcohol included → reject; over-limit → needs_approval per policy rule 6; missing fx rate → abstain) through the logic by hand and they resolve correctly.
