# Held-out evaluation: pre-registration

Committed before any agent wrote a map for these tasks.

- **Suites**: `reply-exposure`, `alert-routing`, `expense-review`, 30 cases each, generated by `gen.mjs`
  with gold computed by rule. None of these tasks, or their suites, was seen while the plugin was
  written or fixed.
- **Arms**: the final plugin (`--plugin-dir plugin`, no hook) against no plugin. The same prompt is used
  in both arms (`run.sh`), and it specifies the map interface so every map is graded by
  `jev-run <suite> --map map.mjs` with no adapter.
- **Runs**: four per arm per task with the session's default agent model, then three per arm per task
  with a second model (`--model sonnet`) for the cross-model check.
- **Metrics**: per map, accuracy (abstain counts as not right), wrong-decision rate, coverage. For
  alert-routing, both fields are graded and a case counts as right only if both are.
- **Hypothesis**: the plugin arm has a lower mean wrong-decision rate and a higher mean accuracy on each
  task. It is reported whatever the result, with per-map numbers.
- **Label audit**: GLM 5.3 Flash relabels all 90 cases from the rule text alone before the maps are
  graded.
- A map that crashes on load is fixed only if the fix is mechanical (a syntax slip), and every fix is
  listed.

## Label audit result (run before any map was graded)

GLM 5.3 Flash agreed on 89 of 90 cases. The one dispute, `exposure-020`, is a draft that sets the
recipient's phone number to a number that, in the generator, belongs to another customer. Nothing in
the case shows that, and the reviewer read it as the customer's own new number. The label is kept as
generated. reply-exposure is reported on all 30 cases and on the 29 undisputed ones.

## Result, default agent model (graded)

| task | plugin: accuracy / wrong | no plugin: accuracy / wrong |
| --- | --- | --- |
| alert-routing | 100% / 0% | 100% / 0% |
| expense-review | 98.3% / **1.7%** | 94.2% / 0% |
| reply-exposure | 96.7% / 0% | 88.3% / 0% |

The accuracy hypothesis holds on two tasks and ties on the third. The wrong-decision hypothesis
**fails on expense-review**: one plugin map made two wrong decisions, both toward caution
(needs_approval instead of approve), and none of the four baseline maps made any. Cause: the map read
the policy's stated limits as bands, so an amount inside the band was "ambiguous" and treated as over.
Rule 5 now says to read a stated number exactly.

## Follow-ups (pre-registered here, before they run)

- **Fix check**: four more plugin runs on expense-review with the refined rule 5. Passes if all four
  maps make 0 wrong decisions.
- **Second agent model** (`--model sonnet`), final plugin, three runs per arm per task. The hypotheses
  are as above.

## Adversarial held-out cases (committed before any map is graded on them)

The first held-out suites proved easy (every arm at 88–100%). `gen-hard.mjs` adds 20 adversarial cases
per task, written after those results but before any map saw them:
- reply-exposure: an order id one digit off, lookalike emails, third parties named by the customer, a
  leaked internal note, staff names, Spanish.
- alert-routing: "P1", "SEV1", "sev2", "This is not critical", a recovered alert, the affected service
  named second.
- expense-review: amounts exactly at, and one cent over, limits; conversions landing either side of a
  limit; "Wine Barrel Grill (food only)" against "a bottle of wine".

GLM 5.3 Flash agreed with all 60 labels. Every held-out map (default model, fix check and second
model) is graded on these with the same hypotheses.

## Result: fix check and second model (graded)

- **Fix check failed.** The four expense maps written with the refined rule 5 made 1, 3, 0 and 1 wrong
  decisions (bar: 0 each). Across every plugin expense map, most wrong decisions (9) were one case,
  "Dinner and a bottle of wine", approved or sent for approval instead of rejected. The maps asked
  whether the expense *is* a never-reimbursable kind. `probe-includes-vs-is.mjs` then measured the two
  wordings: "is it a kind" 10/12 and never decisive, "does it include" **12/12** at 0.93–0.98. Rule 3
  now carries this.
- **Second agent model (Sonnet)**: reply-exposure, plugin 97.8% vs 84.4% accuracy (normal cases) and
  83.3% vs 73.3% (hard); alert-routing 100% both; expense-review, plugin 95.6% vs 92.2% (normal),
  with 1 wrong against 0. One Sonnet plugin map lost 7 cases to gateway 503s, and it is re-run.

## Fix check 2 (pre-registered)

Four plugin runs on expense-review (default model) with the "includes" rule. Graded on normal and hard
cases. Passes if the four maps make at most 2 wrong decisions in total across all 200 graded cases.

**Fix check 2 passed**: 1 wrong decision in total across the four maps and 200 graded cases (bar: at
most 2). One of the four returned a bare label (`"approve"`) instead of `{ decision: "approve" }`, so
strictly it abstained on every case. `jev-run` now accepts a bare label when the gold has one field. No
other map in either arm returned one, and that map scores 50/50 read that way.

## Second model, final plugin (pre-registered)

The Sonnet plugin runs above used the skill before the "includes" rule. Three more Sonnet plugin
runs on expense-review with the final skill, reported against the same Sonnet baseline.

## Regression check after the documentation rewrite (pre-registered)

`jev-questions` was restructured (the rules regrouped and renumbered, with the content kept). Three
plugin runs each on expense-review and reply-exposure, graded on normal and hard cases, plus three runs
of the design A/B `edit` task. The rewrite passes if:
- expense-review makes at most 2 wrong decisions across the 3 maps (150 cases);
- reply-exposure's mean accuracy is at least 93% on normal cases;
- the edit task flags the timeliness comparison in at least 2 of 3 runs.

**Regression check result: passed.**
- expense-review: 1 wrong decision in 150 cases (93.3%, 100%, 100% normal; 100% on all hard cases).
- reply-exposure: 100% on normal cases for all three maps, and 88.3% mean on hard cases (previously 83–88%).
- edit task: 3/3 flagged `notice_timely`, citing the renumbered rules 8 and 9.
