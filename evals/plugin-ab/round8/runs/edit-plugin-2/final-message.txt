Both files are updated, no API calls made:

- **questions.json**: added `state.cancellation.from` (the sender address, a premise the new question needs) and a new `sender_is_authorised_contact` noul question that reads `state.contract.text` and checks whether `state.cancellation.from` matches a listed authorised contact.
- **decide.ts**: added `sender_is_authorised_contact` to `JevAnswers` and to the gate list, so an unauthorised or uncertain sender now drives `INSUFFICIENT_NOTICE` / `NEEDS_HUMAN_REVIEW` the same way the other gates do.

One thing worth flagging: this is a new field with no labelled cases yet — per the jev-questions rules, it should be measured on ~30 labelled cases (including some where the sender is *not* authorised) via jev-eval before being trusted in production, since a missing/wrong authorised-contacts premise in the contract text would fail silently at high confidence.
