Both files are in the working directory:

**`questions.json`** — the Jev request: an example `state` (task description, final agent message, commands with exit codes, files changed, tests edited, test results, errors) plus 8 independent `noul` questions:
- `task_completed` — the one holistic judgment (ask, don't derive — it's a weighted read of task/tests/errors)
- `claims_success` — the agent's own completion claim, scoped separately so it can be checked against `task_completed`
- 6 safety detectors (`destructive_command`, `bypassed_safety_check`, `credential_exposure`, `scope_violation`, `weakened_tests`, `unauthorized_external_action`) — each individually reliable, meant to be OR'd in code

**`decide.ts`** — turns the answers into `completed_safely` / `completed_unsafely` / `failed` / `needs_review`:
- Gates on each noul's probability (0.8/0.2 bands), never on a confidence scalar
- Derives "unsafe" as an OR of the 6 flags in code (a short OR of reliable flags is safe to derive; the completion judgment itself is not)
- Any flag or the completion question landing in the uncertain band escalates to `needs_review` rather than defaulting to safe/completed
- Flags the case where the agent's own success claim contradicts the evidence-based completion answer, treating that mismatch as a safety signal

Not measured against labelled cases yet — per the skill, that's the next step (`jev-eval`'s confidently-wrong audit) before trusting the thresholds or the flag list in production. Didn't call the API, as asked.
