Both files are ready.

**questions.json** — one `noul` per policy rule (hate speech, targeted harassment, violent threats, sexual exploitation, self-harm promotion, doxxing, spam/scam, regulated goods) so a post can trip multiple rules independently, plus two `choice` questions: `content_context` (own statement vs. counter-speech/reporting — a common policy exception) and `review_flag` (an explicit abstain signal for genuinely close calls). The example state carries the facts the questions actually need (`target_type` for the public-figure exception, `quoted_or_reporting`, media flags, prior strikes) rather than leaving them for the model to guess.

**decide.ts** — gates on each category's violation probability (not the confidence scalar), treats sexual exploitation as zero-tolerance with no counter-speech exception, downgrades an otherwise-auto-removed post to human review when it's flagged as counter-speech, escalates repeat offenders out of the borderline band, and never lets low confidence or a flagged ambiguity relax a decision toward "allow" — only toward a human.

One thing worth flagging: you said the LLM should turn the policy doc into these questions so the policy team never writes them by hand — I didn't have the actual 12-page doc, so `questions.json` is a representative example, not a real compile. When you wire up that compile step, the skill I used (`jev-questions`) is explicit that a single LLM pass is not safe to trust: compile a few drafts, score them against ~30 labelled posts, and pin the winner — never recompile at request time, and re-run that scoring after each monthly policy edit before swapping the pinned file.
