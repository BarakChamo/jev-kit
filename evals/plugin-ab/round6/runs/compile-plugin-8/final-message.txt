Wrote both files in the working directory:

**`questions.json`** — the Jev request shape (`model`, `state`, `questions`). State carries the full post text plus parent-post context (the premise a reviewer needs — rule 1), not a pre-extracted summary. Questions are narrow, present-tense, and scoped to named fields (rules 2–4): one `noul` per policy category (violence, hate/harassment, harassment of a private individual, doxxing, adult sexual content, spam/scam, illegal goods, misinfo-causing-imminent-harm, impersonation, CSAM solicitation), plus two `choice` questions — `self_harm_context` (distress vs. encouragement vs. method instructions, since those need different actions) and `context_exception` (journalism/counter-speech/satire, with an explicit `unclear` abstain per rule 9) — and one detector `noul`, `injection_attempt`, for posts that try to talk an automated reviewer into waving them through (rule 10).

**`decide.ts`** — pure logic over the answers, no API call. It never asks Jev for the final verdict holistically (rule 6): it gates each category's probability (not the confidence scalar — rule 8), CSAM bypasses everything at a near-zero threshold, self-harm branches by kind rather than just presence, low-confidence self-harm reads always escalate rather than default to "allow" (rule: low confidence never relaxes a decision), context exceptions only downgrade severity one tier for eligible categories and are voided by a detected injection attempt, and an injection attempt alone flags for review rather than ever loosening an outcome.

One thing worth flagging: `questions.json` here is a hand-built *example* of what the compile step should produce, not a live compile. The actual "policy doc → questions" conversion should happen offline whenever the policy team edits the 12 pages — an LLM drafts a few candidate question maps, each gets scored against a labelled case set (`jev-eval`), and the winner is pinned into `questions.json`. It should never be recompiled per-request — a no-op rewording has been measured to move 82% of answers, so an unpinned live compile would make moderation outcomes drift under a fixed policy.
