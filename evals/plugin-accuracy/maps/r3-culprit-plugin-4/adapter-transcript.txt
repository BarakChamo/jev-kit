`adapter.ts` is written. Summary:

- **`buildState(input)`** — builds `{job_id, repo, branch, command, exit_code, log_lines}` matching the example's shape. `repo`/`branch` and `log_lines` (mapped from the input's flat string array to `{i, text}` with `i` 1-based) come straight from the input; `job_id`, `command`, `exit_code` aren't present in the canonical input under those names, so per the instructions they fall back to the example state's values.
- **`questions(input)`** — copies `is_infra_flake` verbatim, but rebuilds `culprit_line`'s `criteria` from the case's own `log_lines` (since the example's criteria are literal text tied to the example's specific log, not something that generalizes to other cases) while reusing the example's `type`/`instructions` verbatim.
- **`decide(input, answers)`** — calls `decide.ts`'s own `decide()` with the API answer's `choice`/`confidence`/`probabilities` and `noul` fields (no extra convenience fields were needed — decide.ts only reads what the API already returns), then maps its `Verdict` to `{culprit_lines}`: for `confident`/`shortlist` modes, returns the ranked shortlist converted to 0-based indices (`i - 1`); for `infra_flake`/`unclear`, returns `[]`.
